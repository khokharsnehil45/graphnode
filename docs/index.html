GraphNode Documentation

A lightweight, terminal-first system tree, graph architecture, and dependency mapping tool for engineers, architects, and DevOps teams.

💡 The Core Philosophy

Instead of wrestling with drag-and-drop browser tools like Miro or draw.io, GraphNode allows you to scaffold, inspect, audit, and document entire system topologies right from your terminal in seconds.

Installation

Install GraphNode instantly on Linux or macOS with a single curl command:

bash (One-Line Installer) 
curl -sSL https://raw.githubusercontent.com/khokharsnehil45/graphnode/main/install.sh | bash

Or install manually using Python pip:

bash (Manual Install) 
git clone https://github.com/khokharsnehil45/graphnode.git
cd graphnode
pip install .

This installs both the graphnode binary and its convenient shorthand alias gnode.

Quick Start (30 Seconds)

Create a dedicated graph, add services, connect them with protocols, and inspect the hierarchy:

bash 
# 1. Create a graph and auto-generate its dedicated terminal shortcut
graphnode -create my_system

# 2. Command my_system directly!
my_system -add client -type client
my_system -add gateway -type gateway
my_system -add auth_service -type service
my_system -add database -type db

# 3. Connect nodes
my_system -connect client gateway -label HTTPS
my_system -connect gateway auth_service -label gRPC
my_system -connect auth_service database -label SQL

# 4. View visual tree
my_system -show
📦 System Graph: my_system Nodes: 4 | Connections: 3 ─────────────────────────────────────────────────────── └── 💻 [client] (client) └── ──(HTTPS)──▶ 🌐 [gateway] (gateway) └── ──(gRPC)──▶ ⚙️ [auth_service] (service) └── ──(SQL)──▶ 💾 [database] (db)

1. Creating Dedicated Named Graphs

GraphNode features an innovative Dynamic Command Generator. When you create a graph using -create, GraphNode creates an executable script inside ~/.local/bin/<name>.

bash 
graphnode -create graph1

From that moment forward, you can command graph1 directly in your terminal without typing graphnode or specifying flags:

✨ Created new graph 'graph1' 📦 Graph storage : ~/.config/graphnode/graphs/graph1.json 🚀 CLI command : graph1 Active graph set to 'graph1'. You can now run directly: graph1 -add <node_name> graph1 -connect <node1> <node2> graph1 -show

2. Adding Components

Add components one by one, or in batches with single commands:

bash 
# Add single component
graph1 -add api_gateway

# Batch add multiple components at once
graph1 -add service_auth service_billing service_orders worker_email

3. Component Roles & Badges

Assign architectural roles using the -type (or -t) flag. GraphNode recognizes standard cloud and distributed systems roles and displays them with custom visual badges:

4. Wiring Connections

Create directed interactions between components with -connect:

bash 
graph1 -connect client gateway
graph1 -connect gateway auth_service
graph1 -connect auth_service main_db

5. Visualizing the Tree

Render your system tree in the terminal anytime using -show:

bash 
graph1 -show

Edge Protocols & Labels

Real-world systems communicate across heterogeneous network layers. Add -label to declare protocols, methods, or relationships:

bash 
# HTTP / REST
graph1 -connect web_client api_gateway -label HTTPS

# gRPC Microservices
graph1 -connect api_gateway user_service -label gRPC

# Asynchronous message streaming
graph1 -connect user_service kafka_queue -label "pub/sub"

# Database query protocol
graph1 -connect user_service postgres_db -label SQL

Multi-Target Routing

Save time by connecting one upstream service to multiple downstream targets in a single invocation:

bash 
# Connects gateway to service_a, service_b, and service_c
graph1 -connect api_gateway service_auth service_billing service_orders

View Modes: Tree, Card & Flow

GraphNode provides three purpose-built rendering engines:

1. Tree Hierarchy View (-show tree)

Traces dependency paths down to persistence sinks.

2. Architecture Card View (-show card or -list)

Outputs a structured, pipe-delimited component card with in-degree/out-degree counts and incoming/outgoing neighbors:

================================================================= | SYSTEM ARCHITECTURE GRAPH | ================================================================= | Graph Name : graph1 | | Total Nodes : 4 | | Total Edges : 3 | | Entry Points : web_client | | Sinks/Leaves : postgres_db | | Cycles Found : 0 | ================================================================= | [api_gateway] (gateway) | | ──▶ Outgoing (1) : user_service [gRPC] | | ◀── Incoming (1) : web_client | |---------------------------------------------------------------| | [user_service] (service) | | ──▶ Outgoing (1) : postgres_db [SQL] | | ◀── Incoming (1) : api_gateway | =================================================================

3. Direct Arrow Flow (-show flow)

A concise, flat list of direct connections:

Connections in graph1: web_client ──(HTTPS)──▶ api_gateway api_gateway ──(gRPC)──▶ user_service user_service ──(SQL)──▶ postgres_db

Disconnecting & Removing Components

bash 
# Remove connection between two nodes
graph1 -disconnect api_gateway legacy_service

# Delete node and automatically clean up all connected edges
graph1 -remove legacy_service

Health Diagnostics & Metrics (-status)

Run -status to perform an instant diagnostic audit of your architecture:

bash 
graph1 -status
Graph: graph1 (~/.config/graphnode/graphs/graph1.json) • Nodes : 8 • Connections : 9 • Entry Points : web_client, mobile_client (In-degree = 0) • Sinks/Leaves : postgres_db, redis_cache (Out-degree = 0) • Isolated : None • Cycles : 0

Multi-Graph Registry

Manage multiple distinct architectures (e.g. frontend_app, data_pipeline, kubernetes_cluster):

bash 
# 1. Create independent graphs
graphnode -create data_pipeline
graphnode -create kubernetes_cluster

# 2. List all registered graphs
graphnode -graphs

# 3. Switch active context
graphnode -use data_pipeline

# 4. Delete graph and remove its executable shortcut
graphnode -delete-graph old_architecture

Cycle Detection Algorithm

Circular dependencies in microservice architectures cause deadlocks, cascading failures, and infinite retry storms. GraphNode uses a Depth-First Search (DFS) three-color traversal algorithm to detect and alert you to cycles:

⚠️ Cycle Alert in Terminal

When a circular dependency exists (e.g. A ──▶ B ──▶ C ──▶ A), GraphNode flags the node with 🔄 (cycle detected) and aborts infinite recursive loops cleanly.

Diagram & Documentation Exports

Export your terminal graphs into formats for team documentation:

bash (Mermaid Markdown Export) 
# Export to Mermaid flowchart format (renders natively in GitHub & Notion)
graph1 -export mermaid -o docs/architecture.mmd

# Export to Graphviz DOT format (for rendering PNG/SVG via graphviz)
graph1 -export dot -o docs/architecture.dot

# Export full Markdown report with tables and diagrams
graph1 -export markdown -o docs/SYSTEM_SPEC.md

# Export structured JSON
graph1 -export json -o architecture.json

Dual Storage Model

GraphNode balances global convenience with repository version control:

  • Global Named Graphs: Stored in ~/.config/graphnode/graphs/<name>.json. Useful for personal whiteboarding and cross-project system modeling.
  • Project-Level Persistence: Stored in .graphnode.json inside your Git repository. Subdirectories automatically discover the parent project's graph file.
  • Explicit File Flag: Target any custom file using -f /path/to/my_graph.json.
